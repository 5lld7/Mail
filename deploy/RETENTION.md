# حذف حسابات البريد بعد 24 ساعة من أول دخول

يشمل **كل حسابات CyberPanel على كل الدومينات**، حتى الحسابات الموجودة قبل تركيب البانل، وليس فقط `PANEL_DOMAINS`. الحسابات بدون دخول ناجح مرصود لا تُحذف بسبب عمر الحساب.

## معنى أول دخول

`record_login.py` هو Dovecot postlogin hook. بعد نجاح تسجيل دخول IMAP أو POP3 يكتب ملفًا صغيرًا مرة واحدة في مجلد الحساب خارج Maildir. لا يسجل كلمة المرور أو عنوان IP. تكرار الدخول لا يعيد العدّاد إلى الصفر. دخول webmail يُرصد عندما يفتح اتصال IMAP ناجحًا؛ زيارة الصفحة وحدها أو SMTP AUTH للإرسال فقط ليست دخولًا لصندوق البريد.

لا يمكن استنتاج أول استخدام تاريخي للحسابات القديمة من الملفات الموجودة. لذلك المقصود هو **أول دخول ناجح مرصود بعد تركيب المراقب**، وليس تاريخًا تخمينيًا قبل التثبيت. الحسابات القديمة تبدأ من دخولها المرصود التالي. لا يوجد حذف فوري لكل الحسابات عند تشغيل الخدمة.

موعد الاستحقاق هو وقت الدخول + 86400 ثانية. مؤقت systemd يفحص كل دقيقة؛ الحذف قد يتأخر مع توقف السيرفر، أو طول دورة المعالجة، أو تعذر تنفيذ عملية. لا يوجد ضمان للحذف بالثانية ولا يجب اعتبار ظهور القائمة في الواجهة دليلًا على عمل الخدمة.

## ما الذي يُحذف؟

بعد الاستحقاق: حساب CyberPanel ومجلد البريد المحدد تحت `/home/vmail` بما فيه رسائل الحساب وإعداداته الموجودة داخله. يتم فصل جلسات Dovecot وتفريغ auth cache إن كان مفعّلًا. لا يلمس جذر السيرفر أو مجلد الدومين الكامل أو حسابًا آخر.

هذا لا يمحو النسخ الاحتياطية، أو لقطات مزود الاستضافة، أو السجلات، أو الرسائل المحفوظة على أجهزة المستلمين، أو كاش webmail الخارجي عن مجلد الحساب، أو رسائل SMTP الموجودة بالفعل في الطابور. الحذف العادي ليس ضمان محو آمن لقطاعات SSD أو snapshots.

## قبل التفعيل على Ubuntu / Dovecot 2.x

هذه الملفات لم تُختبر على سيرفرك الفعلي بعد. لا تنسخ مثال Dovecot مباشرة قبل مراجعة إعداداتك. `service imap` و`service pop3` قد يستخدمان postlogin موجودًا ويجب الحفاظ عليه وربطه بالسلسلة، وليس استبداله.

من السيرفر، اجمع هذه المعلومات غير السرية فقط:

```bash
sudo doveconf -h libexec_dir
sudo doveconf -h mail_location
sudo doveconf -n | sed -n '/^service imap {/,/^}/p; /^service pop3 {/,/^}/p; /^service .*postlogin.* {/,/^}/p'
sudo systemctl is-active dovecot
```

لا تشارك ناتج `doveconf -n` كاملًا: إعدادات أخرى قد تحتوي على بيانات اتصال. تحقق محليًا من مسار `script-login` داخل `libexec_dir`، ومن أن مسار البريد الفعلي يطابق `/home/vmail/<domain>/<user>/Maildir`. المسارات غير القياسية تحتاج تكييفًا منفصلًا قبل التفعيل؛ لا تغيّر المسار إلى `/` أو `/home`.

1. حدّث ملفات المشروع في `/opt/mail-panel` مع الحفاظ على `/etc/mail-panel.env` و`instance/` وحالة `/var/lib/mail-panel` ومجلدات البريد. اجعل ملفات Python مملوكة لـroot وغير قابلة للكتابة من vmail أو مستخدمي المواقع. `record_login.py` يجب أن يكون قابلًا للتنفيذ (0755) وبقية ملفات التطبيق قابلة للقراءة من vmail (0644)، والمجلدات 0755.
2. المثال `deploy/dovecot-postlogin.conf.example` يستخدم خدمة postlogin باسم مستقل، ويفترض المسار القياسي لـDovecot. راجعه مع إعداداتك الحالية. خذ نسخة من ملفات إعداد Dovecot التي ستعدلها، ثم أضف الإعداد في ملف مشمول فعليًا من Dovecot. لا تستبدل إعداد postlogin موجودًا.
3. تحقق من الصياغة دون طباعة الإعدادات: `sudo doveconf -n >/dev/null`. إذا فشل، استرجع ملف الإعداد السابق قبل عمل reload. عند نجاحه نفذ `sudo systemctl reload dovecot` واختبر عمل البريد فورًا.
4. سجّل الدخول إلى حساب اختبار عبر webmail أو IMAP، ثم اعرض تبويب «الحذف بعد 24 ساعة» بالبانل. لازم يظهر موعد محدد للحساب بعد الدخول. سجّل الدخول مرة ثانية وتأكد أن الموعد لم يتغير. لا تعدّل timestamps على حسابات حقيقية لتسريع الحذف.
5. اعمل معاينة بدون حذف من داخل مجلد المشروع:

```bash
cd /opt/mail-panel
sudo .venv/bin/python expiry_worker.py
```

المعاينة لا تحذف حسابات أو ملفات؛ قد تنشئ مجلد حالة وقفلًا فقط. عدم ظهور حسابات مستحقة قبل مرور 24 ساعة طبيعي. اختبارات المشروع تستخدم مجلدات مؤقتة وحسابات وهمية لاختبار الاستحقاق والحذف الفعلي وإعادة المحاولة.

## تفعيل مؤقت الحذف بعد التأكد من المراقبة

تفعيل المؤقت يعني السماح بالحذف النهائي لكل الحسابات التي تبدأ عدّادها بالمراقب. يجب أن يكون `/etc/mail-panel.env` موجودًا، و`PANEL_MODE=cyberpanel`، وخدمة البريد تعمل.

```bash
sudo cp deploy/mail-panel-expiry.service deploy/mail-panel-expiry.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now mail-panel-expiry.timer
sudo systemctl list-timers mail-panel-expiry.timer --no-pager
```

للتحقق من النتيجة: `sudo journalctl -u mail-panel-expiry.service -n 50 --no-pager`. الواجهة تعرض الحسابات المستحقة والحذف المعلق، لكنها لا تتحقق تلقائيًا من تثبيت hook أو حالة المؤقت.

للإيقاف: `sudo systemctl disable --now mail-panel-expiry.timer`. ده يوقف الدورات القادمة فقط؛ لو فيه دورة تعمل حاليًا راجع حالتها. لا يحذف سجلات أول دخول؛ لو أعدت التفعيل، تظل المواعيد السابقة كما هي.

## الفشل وإعادة إنشاء الحساب

قبل إزالة سجل الحساب تُحفظ عملية معلقة في `/var/lib/mail-panel` بصلاحيات root فقط. لو فشلت إزالة البيانات بعد حذف الحساب، الخدمة تعيد المحاولة في الدورات القادمة، والواجهة تعرض العنوان كعملية غير مكتملة. لا تعتبر ظهور خطأ دليلًا على أن الحساب لم يتغير.

عند نتيجة مبهمة لحذف سجل الحساب أو ظهور حساب بديل بنفس العنوان/مجلد بديل، يتوقف الحذف لهذا العنوان للمراجعة بدل حذف البديل. لا تمسح ملفات العمليات المعلقة أو علامات أول دخول لتجاوز الخطأ. لا تعد إنشاء العنوان من CyberPanel أثناء وجود حذف معلق. البانل يمنع إعادة الإنشاء عند وجود عملية معلقة أو مجلد بريد قديم بنفس الاسم.

بعد الحذف المكتمل يمكن إنشاء العنوان من جديد؛ يبدأ انتظار أول دخول جديد. العمليات اليدوية في CyberPanel أو SSH لا تشترك في قفل البانل؛ لا تتزامن بها مع الحذف التلقائي، ولا تعِد استخدام Maildir قديم لحساب جديد بدون مراجعة علامة أول دخول.
