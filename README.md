# بريد — بانل خفيف لإدارة CyberPanel

واجهة عربية لإنشاء حسابات البريد وعرضها وحذفها، وعرض مساحة قرص النظام، ومعاينة وتنظيف بعض الملفات المؤرشفة. Python 3.10+ وFlask وWaitress فقط، بدون Node أو Redis أو قاعدة بيانات إضافية في الوضع الفعلي.

## الموجود حاليًا

- دخول بكلمة مرور محفوظة كـhash، جلسة 30 دقيقة، CSRF وتحديد محاولات الدخول.
- السماح بدومينات محددة فقط، وتأكّد من نتيجة إنشاء وحذف البريد بإعادة قراءة الحسابات.
- تأكيد بعنوان البريد الكامل قبل حذف الحساب. الحذف الفعلي يزيل سجل CyberPanel، ويفرغ كاش المصادقة عند تفعيله، ويفصل جلسات Dovecot، ثم يحذف مجلد `/home/vmail/<domain>/<user>` ورسائله. CyberPanel وحده قد يترك المجلد، لذلك يتم التحقق من إزالته صراحة.
- معاينة الملفات والحجم قبل التنظيف، ثم تأكيد صريح. المعاينة صالحة 5 دقائق وتستخدم مرة واحدة.
- التنظيف يقتصر على ملفات مباشرة أقدم من 14 يومًا: لوجات مضغوطة أو مرقمة في `/var/log` و`/usr/local/lsws/logs`، وحزم `.deb` في `/var/cache/apt/archives`.
- لا يتبع روابط رمزية، ولا يحذف مجلدات أو ملفات لها hard links، ويتخطى الملفات التي تغيرت بعد المعاينة. حد أقصى 1000 ملف لكل دفعة.
- لا يوجد حذف عام لأي مسار، أو تنظيف مواقع أو قواعد بيانات أو رسائل بريد أو backups. تحديد سياسة للنسخ القديمة يحتاج معرفة مكانها ومتطلبات الاحتفاظ بها أولًا.

## تجربة محلية بدون CyberPanel

من داخل مجلد المشروع:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
export PANEL_MODE=demo
export PANEL_DOMAINS=example.com
export PANEL_SECRET="$(.venv/bin/python -c 'import secrets; print(secrets.token_hex(32))')"
export PANEL_PASSWORD_HASH="$(.venv/bin/python app.py --hash-password)"
.venv/bin/python app.py
```

الخدمة تستمع على `127.0.0.1:8095`. استخدم متصفحك المحلي أو tunnel. كلمة المرور تدخل تفاعليًا ولا يوجد حساب افتراضي. في وضع demo حسابات البريد مجرد بيانات تجريبية في `instance/demo.sqlite3`؛ لا يُنشأ بريد حقيقي ولا تُحذف ملفات السيرفر. الواجهة تعرض الوضع بوضوح.

## تشغيل على سيرفر CyberPanel

هذه خطوات تجهيز للنشر، ولم يتم تنفيذها على سيرفرك. مطلوب Linux مع systemd وPython 3.10+ وCyberPanel مثبت وخدمة بريد تعمل ودومين موجود بالفعل. التكامل مبني على `plogical.mailUtilities` في الكود الرسمي لـCyberPanel (مرجع `277cc4cacf18d286b2ebe1aab1b10d0281b0f91e`)؛ يحتاج اختبار توافق مع إصدارك، خصوصًا الإصدارات القديمة. لا يتم تعديل ملفات CyberPanel.

1. ضع المشروع في `/opt/mail-panel`، وثبّت البيئة الافتراضية هناك بالأوامر السابقة. لا تستخدم بيئة Python الخاصة بـCyberPanel لتثبيت Flask.
2. انسخ `.env.example` إلى `/etc/mail-panel.env`. اضبط `PANEL_MODE=cyberpanel` و`PANEL_DOMAINS` على الدومينات الحقيقية، وولّد `PANEL_PASSWORD_HASH` بالأمر `.venv/bin/python app.py --hash-password` و`PANEL_SECRET` بالأمر `.venv/bin/python -c 'import secrets; print(secrets.token_hex(32))'`. احفظ القيم في الملف محليًا، ولا ترسلها في الشات أو ترفعها إلى Git.
3. اجعل ملف الإعدادات مملوكًا لـroot وصلاحياته `600`، ومجلد المشروع وبيئته الافتراضية مملوكين لـroot وغير قابلين للكتابة من مستخدمي المواقع.
4. تحقق من وجود `/usr/local/CyberCP/bin/python`؛ عدّل `PANEL_CYBER_PYTHON` عند الحاجة. الخدمة تستدعي helper بهذا المفسر وتستخدم إعدادات Django الحالية لـCyberPanel. كلمات مرور البريد تنتقل عبر stdin، وليست arguments ظاهرة في قائمة العمليات ولا تُسجَّل بواسطة البانل.
5. ثبّت خدمة systemd:

```bash
sudo cp deploy/mail-panel.service /etc/systemd/system/mail-panel.service
sudo chmod 600 /etc/mail-panel.env
sudo systemctl daemon-reload
sudo systemctl enable --now mail-panel
sudo systemctl status mail-panel
```

النسخة الحالية تستخدم صلاحيات root لأن إدارة البريد والتنظيف يحتاجان صلاحيات إدارية. تشغّل خدمة واحدة وأربع threads فقط. لا تعرضها مباشرة على الإنترنت؛ الربط مقيد بـloopback. للوصول من جهازك:

```bash
ssh -L 8095:127.0.0.1:8095 your-server-user@your-server
```

افتح عنوان loopback على جهازك بعد الاتصال. كبديل يمكن إعداد reverse proxy مع HTTPS على السيرفر، ثم ضبط `PANEL_SECURE_COOKIE=1`. لا تفتح بورت 8095 للعامة. لا يلزم باسورد CyberPanel في إعدادات البانل لأن التكامل محلي.

قبل الاعتماد: اعرض الحسابات الفعلية لدومين تجريبي، وأنشئ حسابًا تجريبيًا ثم احذفه من البانل، واختبر إرسال واستقبال البريد منفصلًا. إعدادات DNS وMX وSPF وDKIM وPTR ليست ضمن هذا المشروع ولا ينفذ البانل إعدادها تلقائيًا. معاينة التنظيف لا تحذف شيئًا، ولا تعني أن كل ملف قديم غير مطلوب؛ راجع القائمة قبل التأكيد. تقدير حجم الملفات لا يضمن نفس الزيادة في المساحة المتاحة إذا كانت خدمة ما لا تزال فاتحة الملف.

لتشخيص الخدمة: `sudo journalctl -u mail-panel -n 100`، ولإيقافها: `sudo systemctl stop mail-panel`. السجل يتضمن عمليات الإنشاء والحذف وأعداد الملفات، ولا يسجل كلمات المرور بواسطة التطبيق.

## الحذف التلقائي بعد أول دخول

راجع [دليل التفعيل](deploy/RETENTION.md). يشمل كل الحسابات على كل الدومينات بعد 24 ساعة من أول دخول ناجح مرصود بعد تركيب Dovecot postlogin hook. تمت إضافة تبويب لعرض الموعد والحذف المعلق، وخدمة مستقلة تعمل كل دقيقة حتى لو البانل مغلق. هذه الميزة تحتاج تركيب المراقب والتحقق منه على السيرفر ثم تفعيل المؤقت صراحة؛ رفع الملفات وحده لا يشغلها. الوضع التجريبي لا يحذف حسابات حقيقية.

خيار «تنظيف شامل» يجمع معاينة فئات اللوجات المؤرشفة وكاش الحزم فقط، بنفس شروط العمر والتحقق قبل الحذف. لا يزيل برامج السيرفر أو ملفات المواقع أو journald أو النسخ الاحتياطية تلقائيًا. تحويل السيرفر إلى بريد فقط يحتاج جردًا للخدمات والاعتمادات قبل إزالة أي مكون.

## التحقق والاختبارات

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python tests/smoke_http.py
node --check static/app.js
```

تختبر تسجيل الدخول وCSRF وحدود المحاولات ودورة إنشاء/حذف البريد التجريبي، ورفض الدومينات غير المسموحة، وتأكيد التنظيف وانتهاء المعاينة وعدم إعادة استخدامها، وحماية الملفات النشطة والمتغيرة والروابط الرمزية. لا تتصل الاختبارات بسيرفر حقيقي.

اختبار واجهة اختياري عند توافر Playwright و`/usr/bin/chromium`: `python3 tests/smoke_browser.py`. يتحقق من التفاعل الفعلي على سطح المكتب والموبايل، ولا يضيف اعتمادًا لتشغيل البانل.
